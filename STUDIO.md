# Studio du portfolio (copie privée éditable + bouton « Publier »)

Le contenu du site (textes, projets, expériences, traductions, images…) vit dans `content/site/*.json`. Les pages le lisent via `lib/site-content.ts`.
Le **studio** (`/studio`) est un éditeur de ces JSON, avec aperçu du site en direct, sur une **copie privée** :

```
 Vous ──► studio (copie privée, protégée Vercel)  ── brouillon ──►  branche GitHub « studio-draft »
                                                                              │  « Publier » = 1 commit de contenu
 Visiteurs ◄── site public (Vercel, build statique)  ◄── redéploiement ◄──  branche « main »
```

- **Site public** : `STUDIO_MODE` absent → `/studio`, `/api/studio/*` répondent 404 ; le contenu est embarqué au build (statique, rapide).
- **Studio** : `STUDIO_MODE=1` → les pages lisent le **brouillon** à la volée (modifier → l'aperçu change tout de suite, sans rebuild).
- **Publier** : crée UN commit sur `main` avec seulement les fichiers de contenu modifiés (`content/site/*.json`, `public/uploads/*`) ; Vercel redéploie le site public (≈ 1 min). Le code n'est jamais touché. Annuler une publication = `git revert`.

## Édition directe sur le site (le mode principal)
Sur la copie privée, **le site est exactement le vôtre** ; une pastille en bas à droite permet d'éditer dessus :
- **Éditer le site** : active le mode édition (mémorisé).
- **Modifier un texte** : cliquez dessus (titre, paragraphe, bouton, description de projet…) → petit éditeur au même endroit → Entrée. Le texte change aussitôt dans la page et dans le brouillon.
- **Ajouter / supprimer / déplacer** : survolez un bloc (un projet, une expérience, une étape, un outil, un essai…) → barre d'outils ↑ ↓ **dupliquer** (= ajouter une copie, avec un nouvel identifiant) **supprimer**. `↰` choisit le niveau (le projet entier ou un de ses éléments).
- **Remplacer une image** : survolez-la → « Remplacer l'image » (envoi + remplacement partout où elle est utilisée).
- **À publier / Publier** : compteur de modifications, comparaison avec le site public, publication.
- **Tout ce qui s'affiche se modifie** : textes des données et des pages, champs de liaison (société, catégorie, étiquettes, technologies, **dates** même affichées « juillet 2025 ») retrouvés par leur valeur — avec la case « appliquer aux autres occurrences » quand une valeur sert de lien entre plusieurs contenus —, **textes d'attributs** (texte alternatif des images, texte d'aide des champs de formulaire, info-bulles : survolez l'élément → pastille), **images** des données (nouvelle image, chemins mis à jour) et **images fixes du site** (logos, visuels : même chemin, nouveau fichier, publié avec le reste).
- Les textes transformés par le code (majuscules, troncatures) se recalent d'eux-mêmes après l'enregistrement (rafraîchissement du rendu serveur).
- Cas particuliers : un texte *calculé* (ex. la ligne « IA : OpenAI, … » d'une carte projet) se modifie à la source (ses technologies) ; le code de langue « FR / EN » et les libellés invisibles des carrousels restent dans le code.
- **Thème** (pastille) : couleurs du site en mode clair et sombre (fond, texte, cartes, accent, boutons, bordures…), arrondi des coins, police. L'aperçu est immédiat ; les valeurs sont dans `content/site/theme.json` et injectées en CSS (`lib/site-theme.ts`). Seules les couleurs-jetons du site sont concernées (pas les couleurs fixes comme l'ambre des étapes de « À propos »).
- **Sections** : survolez une section → barre « Section » : **réglages** (fond : carte / atténué / accent / sombre / couleur libre, espacement vertical, largeur étroite, alignement), monter / descendre, **masquer**, **ajouter une section après celle-ci**, supprimer (sections ajoutées). La pastille « Sections » liste toutes les sections de la page (y compris masquées) pour les réordonner ou les réafficher. Les réglages sont dans `content/site/layout.json` (règles CSS par page, `components/blocks/LayoutRules.tsx`).
- **Nouvelles sections** : titre, texte, image + texte, cartes, galerie, citation, appel à l'action, liste, séparateur (`lib/studio/block-templates.ts`, rendu `components/blocks/Block.tsx`). Elles s'ajoutent à toutes les pages du site (portfolio, projets et détail d'un projet, expériences et détail, À propos, Uses, essais et détail, articles, newsletters, EN) : survolez une section → « + Ajouter une section ici » (bord inférieur) ou « + Section » dans la barre ; la pastille « + Section » ajoute à la fin de la page et se modifient ensuite comme le reste (clic sur un texte, remplacement d'image…).
- **Copier / coller des sections existantes (copie exacte)** : dans la barre « Section » d'une section, **Copier** (puis **Coller** sur n'importe quelle page : barre « Section », menu « + Section » ou pastille « Coller »), **Dupliquer** (copie juste après) ; ou « + Section » → **Reprendre une section existante du site…** : choisissez une page, puis une de ses sections. La copie est le HTML déjà rendu (mêmes classes, donc même apparence en clair et en sombre) : les textes et les images de la copie se modifient ensuite librement et indépendamment de l'original. Les interactions (carrousels, formulaires, bascules) ne sont pas reprises. Une section ajoutée (« Cartes »…) est clonée avec ses données. Garde-fous : HTML nettoyé par liste blanche, jamais de script ni de formulaire (`lib/studio/html-safe.ts`, refus côté serveur).
- **Nouvelles pages** (pastille « Pages ») : créez une page → `/p/<identifiant>` avec ses sections. Pour la relier au site, ajoutez-y un lien (section « Appel à l'action » ou « Cartes », lien `/p/<identifiant>`). Contenu dans `content/site/pages.json`.
- **Formulaires** : l'éditeur par formulaires (`/studio`) reste disponible pour les champs invisibles (liens, dates, identifiants, catégories).
Comment ça marche : sur la copie privée seulement, chaque texte affiché est suivi d'une signature invisible (caractères de largeur nulle) qui dit de quel champ il vient (`lib/studio/stega.ts`). Ni identifiants, ni liens, ni dates, ni filtres ne sont signés. Rien de tout cela n'existe sur le site public.

## Utilisation locale (aucune configuration)
```bash
STUDIO_MODE=1 pnpm dev      # http://localhost:3000/studio
```
Stockage « fichiers locaux » : le brouillon = vos fichiers, le publié = le dernier commit git. « Publier » crée un commit local (contenu uniquement) ; poussez-le vous-même.
(Pour que les comparaisons fonctionnent, `content/site/` doit être commité une première fois.)

## Mise en place du studio en ligne (une seule fois)
1. **Pousser le code** de la branche `feat/studio` et la fusionner dans `main` (le site public se met à jour, identique visuellement).
2. **Jeton GitHub** : GitHub → Settings → Developer settings → Fine-grained tokens → dépôt `Portfolio-gabriel-bigot` uniquement, permission **Contents : Read and write**. Ne le collez jamais dans une conversation ou un fichier du dépôt.
3. **Projet Vercel « gabriel-bigot-portfolio-studio »** : même dépôt, branche de production `main`, variables d'environnement :
   - `STUDIO_MODE=1`
   - `GITHUB_TOKEN=<le jeton>` ; (facultatif) `GITHUB_REPO`, `PUBLISH_BRANCH=main`, `DRAFT_BRANCH=studio-draft`
4. **Protection** : Vercel → projet studio → Settings → Deployment Protection → *Vercel Authentication* sur **tous** les déploiements (y compris la production du projet).
5. Ouvrir `https://<projet-studio>.vercel.app/studio`.

Le projet public ne reçoit AUCUNE de ces variables.

## Ce qui est éditable
Tout le contenu visible du site :
- les **données** (profil, réseaux, compétences, formation, expériences FR/EN, entreprises, projets FR/EN, essais, étapes de « À propos », outils de « Uses », référencement) ;
- **tous les textes des pages** (titres de sections, libellés de boutons, légendes, messages du formulaire de contact, métadonnées de page…), dans « Tous les textes des pages » : un bloc par page ou composant, une ligne par texte. Dans le code, ces textes sont des appels `t("clé")` (`lib/strings.ts`) ;
- les **images** (téléversement → `public/uploads/`).
Éditeur générique : champs texte, longs textes, nombres, interrupteurs, listes (ajouter / dupliquer / déplacer / supprimer), JSON brut.
Ajouter un nouveau texte dans une page : écrire `t("ma-cle")` dans le code, ajouter la clé dans `content/site/strings.json`, puis `pnpm content:check` vérifie que tout est cohérent.

## Modifications faites ailleurs : fusion et conflits
Si le site publié change pendant que votre brouillon contient des modifications (autre publication, correction faite en dehors du studio, autre appareil), le studio **met le brouillon à niveau tout seul** :
- un fichier modifié seulement d'un côté est repris tel quel ;
- un fichier modifié des deux côtés est **fusionné champ par champ** (listes d'éléments rapprochées par `id`/`slug`, listes d'étiquettes fusionnées) ;
- seuls les champs modifiés **des deux côtés, différemment** sont en conflit : votre version est conservée, le fichier est signalé, la publication est bloquée, et la fenêtre « Changements » propose « Garder ma version » ou « Prendre la version publiée ».
Le code de `main` n'est jamais écrasé : une publication ne contient que des fichiers de contenu.

## Garde-fous
- Routes d'écriture : 404 sans `STUDIO_MODE`, refus des requêtes d'un autre site, chemins limités à `content/site/*.json` et `public/uploads/*`, images vérifiées par leur contenu (pas de SVG, 8 Mo max), la structure racine d'un contenu ne peut pas changer.
- « Annuler les modifications » ne supprime jamais un fichier de contenu qui n'a pas de version publiée (la première fois, commitez `content/site/`).
- Le jeton GitHub n'existe que dans le projet studio.

## Articles (essais et dossiers fusionnés)
**Un seul type d'écrit : l'article.** Le format article (couverture, sommaire numéroté, sections, sources à pastilles, graphiques, encadrés) est la base ; un « essai » est simplement un article sans sources chiffrées (étiquette `series: "Essais"`). Les anciens essais de `content/site/blog-posts.json` ont été migrés une fois par `node scripts/migrate-essays.mjs` (coupés aux titres en sections ; les sous-points « 1. … » restent des sous-titres ; aucun texte perdu ; le fichier d'origine est conservé tel quel et n'est plus utilisé). Les adresses `/blog` et `/blog/<slug>` redirigent vers `/articles` et `/articles/<slug>`. Il n'y a plus d'éditeur d'essais : tout passe par « + Article » (barre du site) ou le panneau Articles, « ✨ Nouvel article avec Claude » compris.

### Une seule logique : les blocs (éditeur d'écriture)
Tous les articles, y compris les dossiers importés du skill `dossier-article`, s'écrivent désormais dans le même éditeur à blocs (`/studio/write/article/<slug>`, bouton « ✎ Éditer » de l'aperçu). Les dossiers importés ont été **adoptés** par `node scripts/adopt-dossiers.mjs` : chaque élément du HTML d'origine devient un bloc éditable (texte, chapô, titres, listes, encadrés, tableaux, glossaire, figures avec leur numéro et leurs sources) **seulement si le bloc re-rendu redonne exactement le même HTML** ; sinon l'élément est gardé tel quel dans un bloc « HTML d'origine » (explications interactives, schémas, registre…), déplaçable et supprimable mais pas éditable en texte. Garde-fou : le rendu converti de chaque dossier doit être identique au rendu d'origine (sections et sommaire), sinon le dossier n'est pas touché ; `--dry` montre le résultat sans rien écrire. Sauvegarde : `_original/` dans chaque dossier ; `node scripts/adopt-dossiers.mjs --restore <slug>` remet l'ancien état. La couverture (chiffres clés, métadonnées) reste celle du HTML d'origine ; seuls le titre et le chapô sont modifiables dans l'éditeur.

## Articles (dossiers)
Le panneau « Articles (dossiers) » liste les articles, ouvre l'éditeur de notes/sous-articles et règle le statut brouillon/public. Notes, images et manifeste suivent le même cycle brouillon → « Publier… » que le reste. Détails : `ARTICLES.md`.

### Créer une page vierge
- **Essai** : « + Nouveau → Essai vierge » (barre du site) ou le bouton de la liste des essais. L'écriture se fait **directement sur la page de l'essai** (`/blog/<slug>`, rendu réel ; titre et accroche restent éditables en place comme le reste du site). L'éditeur plein écran `/studio/write/<slug>` existe toujours : blocs façon Notion — **menu « / »** (texte, titres, listes, citation, code, image, séparateur), **Entrée** = nouveau bloc, **Retour arrière** sur un bloc vide le supprime, raccourcis Markdown (`# `, `- `, `1. `, `> `, `---`, `**gras**`, `*italique*`, `` `code` ``), glisser ⋮⋮ pour réordonner, barre à la sélection (gras, italique, code, lien, ✨ réécrire avec Claude), **✨ Écrire avec Claude** depuis « / », et **✨ Plan guidé** : Claude propose les parties et, pour chacune, le format conseillé (paragraphe, liste, tableau, graphique…) avec la raison ; pour un graphique, les formes classées par le modèle de décision du skill `dossier-article`. Enregistrement automatique dans le brouillon. **Graphiques dans un essai** : « / graphique » ou la proposition automatique de Jev (passage chiffré) ; collez les données, choisissez la forme classée par le modèle de décision, ajoutez une source en texte libre. La figure est enregistrée dans l'essai (`content[].figure`) et dessinée sur la page par le moteur des dossiers dans un cadre isolé (`/figure-engine/frame.html`, fichiers dans `public/figure-engine/` ; clair/sombre suivi). Les mêmes outils existent dans l'éditeur des dossiers.
  Il demande un titre, ajoute l'essai en tête, **non publié** (`published: false`) ; le studio l'affiche quand même pour que vous le rédigiez en place (clic sur un texte, « + Section »). Tant qu'il n'est pas marqué publié, le site public n'affiche que son titre avec « à venir ».
- **Article (dossier)** : « + Nouveau → Article vierge » (barre du site) ou « + Nouvel article vierge » dans le panneau Articles ; « ✎ Écrire » (panneau Articles, ou barre de l'aperçu du dossier) ouvre l'**éditeur d'écriture des dossiers** (`/studio/write/article/<slug>`) : la page est rendue avec la feuille de style du dossier (couverture, sommaire qui se met à jour, sections numérotées, encadrés, figures numérotées), et l'on écrit directement dedans. Sur les essais, le sommaire de la page se met à jour en direct pendant l'écriture. Même forme que les dossiers du skill : couverture, **sommaire automatique** et sections numérotées (réordonnables ↑ ↓), puis dans chaque section les mêmes blocs que les essais plus : chapô, **encadrés** (À retenir / Position de l'auteur / Attention), **tableaux**, **glossaire**, **citer une source** (pastille K : choisir dans le registre ou ajouter une source avec date, état de la preuve, limites), et **graphiques**. Le registre des sources est généré en dernière section. Les sections écrites là sont stockées dans `content/articles/<slug>/edits.json` (`pages[""].added[].blocks`, sources dans `evidence`, figures dans `figures`) ; l'édition en place est désactivée sur elles. Sur un dossier **importé**, l'éditeur n'ajoute que de nouvelles sections (après celles d'origine).
- **Jev ambiant (sans menu)** : pendant que vous écrivez, après une courte pause, des propositions discrètes apparaissent sous le bloc (« Oui » / « Ignorer ») : 📊 un passage qui compare ≥ 3 éléments chiffrés, décrit une évolution (≥ 3 dates) ou une liste « libellé : valeur » → graphique prérempli avec vos chiffres, aperçu et formes classées ; 🔎 un chiffre sans source → citer une source ; ✨ un premier paragraphe-thèse → plan guidé (un format conseillé par partie, sections créées avec une note « [À compléter…] ») ; ✨ une phrase qui ressemble à une consigne (« Écris… », « Explique… ») → ↵ l'envoie à Claude. La détection est locale (aucun appel IA tant que vous n'acceptez pas) ; les données proposées viennent mot pour mot de votre texte. Le menu « / » reste disponible.
- **Consignes à Jev** (tapées dans un bloc vide, puis ↵ ou « Oui » ; le bloc de consigne disparaît) :
  - *Sans IA, instantanées* : « mets le mot X en gras / italique / code », « enlève le gras de X », « remplace A par B », « supprime le mot X », « mets un lien sur X vers https://… », « mets ce paragraphe en citation / encadré / liste / sous-titre / chapô », « transforme la liste en paragraphe », « mets tout le paragraphe en gras », « monte / descends ce paragraphe », « fusionne avec le paragraphe précédent », « coupe la section ici », « supprime la section X », « supprime le dernier paragraphe », « relis la section / l'article » (doublons, sigles non définis, figures non commentées, chiffres sans source, affirmations très fortes, sections trop longues ; bouton « Relecture critique par Claude »).
  - *Avec Claude* (annulables, marqués à relire) : « raccourcis / simplifie / reformule / corrige les fautes / traduis en anglais » (le paragraphe du dessus), « donne-moi 3 titres possibles pour cette section » (choix à cliquer), « résume l'article en 3 phrases » (remplit le Résumé), « ajoute une conclusion » (section « Ce qu'il faut retenir »), « c'est quoi X ? » (définition ou glossaire), « cherche des sources sur X » (pistes de recherche à vérifier : Claude n'a pas le web et n'invente aucune source), « mets-le en courbe / barres / camembert… » (convertit la figure en gardant les données).
  - *Propositions automatiques* : section de plus de 450 mots → la couper ; six paragraphes d'affilée → insérer un encadré ; article de 800 mots et plus sans conclusion → « Ce qu'il faut retenir » ; deux valeurs comparées dans le texte → graphique ; tableau collé depuis Excel → vrai tableau avec bouton « 📊 Graphique depuis ce tableau ».
- **États de chargement** : pendant qu'un graphique se crée, un emplacement animé (barres qui pulsent, compteur de secondes) occupe sa place dans l'article ; une pastille « ✨ Claude … · N s » au centre bas indique les opérations de texte en cours (écriture, interprétation, lecture des chiffres) mais pas la création, le dessin ni le redessin d'un graphique, déjà signalés par leur emplacement animé ; un texte en cours d'écriture pulse avec « Claude écrit… » sous lui ; au-delà de 12 s le message précise que ça continue.
- **Graphique dessiné par Claude d'abord, galerie ensuite** : quand vous demandez un graphique (« fais un graphique de ça », « sur la lune »…) et que la clé IA est présente, Claude **dessine lui-même** un graphique ou un schéma en SVG à partir des chiffres du texte (couleurs par variables du dossier : thème clair/sombre respecté, lisible en largeur réduite). Il n'utilise que des chiffres écrits dans le texte et signale ceux qui n'y figurent pas (graduations d'axe exceptées). Le SVG est assaini côté serveur (aucun script, aucune image ni adresse externe). Sous la figure : une case « Demander une modification » (« plus simple », « change les couleurs », « ajoute une légende ») et le bouton **« Utiliser un graphique de la galerie »**, qui remplace le dessin par une forme de la galerie choisie par le modèle de décision à partir des mêmes données (ou dites « prends un graphique de ma galerie »). Pour passer directement par la galerie : « fais un graphique de ça dans ma galerie ». Sans clé IA, la galerie est utilisée.
- **Graphique sur un thème** : « fais un graphique sur ce qui concerne la lune » (ou « sur les ventes », « pour le chômage ») cherche dans tout l'article les passages qui parlent du thème, en tire les chiffres explicitement écrits (jamais déduits) et crée le graphique ; s'il n'y en a pas assez, Jev le dit.
- **Graphique depuis un passage** : « fais un graphique de ça » (ou « génère une courbe avec ces chiffres », même avec des fautes de frappe : « fait un graphique pou ça ») prend la sélection épinglée, sinon le paragraphe du dessus. Les chiffres sont repérés localement (« 12,5 % des actifs en France, 9,8 % en Allemagne… », « respectivement », « de 8 à 12 % »), sinon Claude les extrait, et seules les valeurs écrites dans le texte sont gardées (rien n'est déduit ni calculé). Le graphique est créé directement, sans fenêtre de confirmation : pour en changer les valeurs ou la forme, « Modifier les valeurs ou la forme » (au-dessus de la figure) rouvre la fenêtre avec les valeurs actuelles. Même chose pour les propositions automatiques (chiffres, frise, tableau → graphique). La fenêtre n'apparaît d'office que pour « / graphique » ou si les données ne se lisent pas.
- **Sélection épinglée** : le passage que vous sélectionnez reste surligné en violet (et résumé dans une pastille 📌 en bas à gauche) même quand le curseur va ailleurs, jusqu'à ce que vous disiez à Jev quoi en faire dans n'importe quel bloc : « mets ça en gras / italique / code », « mets un lien vers https://… », « remplace ça par … », « supprime ça », « raccourcis / simplifie / reformule / corrige / traduis ça », « explique ça » (nouveau paragraphe après le passage), « c'est quoi ça ? », « trouve une source pour ça ». **Tant qu'un passage est épinglé, il est joint comme contexte à tout ce que vous demandez à Claude** (consigne libre, question, réponse, réécriture, graphique), même si votre phrase ne dit pas « ça » : Claude sait que vous parlez de ce passage. Une courte phrase écrite pendant qu'un passage est épinglé propose d'être interprétée comme consigne (sans capter ↵ si rien n'indique que c'en est une). Un nouveau passage sélectionné remplace l'ancien ; ✕ désépingle. Le balisage (gras, lien) est respecté : on enveloppe un lien ou un passage en gras entier plutôt que de le couper.
- **Provenance des textes écrits par Claude** : un texte écrit par Jev/Claude est souligné en violet ; au survol s'affichent *votre demande*, le texte d'avant, l'état (« à relire » / « modifié depuis ») et deux boutons : « Annuler l'IA » (remet le texte d'avant, ou supprime le bloc créé) et « Marquer comme relu ». La provenance est enregistrée avec l'article (jamais publiée).
- **Réponse directe** : l'écriture de Claude (réécriture, « continue », réponse à une question, phrase suivante avec Tab, consigne libre) est appliquée tout de suite, sans fenêtre de confirmation ; une bulle « Annuler » reste affichée quelques secondes et le survol du texte violet rappelle votre demande.
- **Consigne libre** : une phrase d'édition que les règles ne comprennent pas (« mets ce mot en évidence », « ajoute un paragraphe qui dit… », « range… ») est envoyée à Claude, qui répond par une liste d'actions de la même grammaire que les consignes locales (jamais du texte inventé) ; les actions sont appliquées directement (annulables). Les propositions ne s'empilent plus : une seule s'affiche, avec « +N autres ».
- **Détections supplémentaires** : « respectivement », « de 8 à 12 % », frise chronologique (≥ 3 événements datés), pour/contre → tableau, définition dans le texte → glossaire, chiffre incohérent entre sections, chiffre du texte différent de celui d'une figure (aussi dans « relis l'article »).
- **Sources** : « Citer une source » classe d'abord les sources du registre qui ressemblent au passage ; « Compléter » lit les métadonnées d'une adresse (titre, éditeur, date : à vérifier, adresses locales refusées).
- **Historique des versions** (bouton 🕘 de l'éditeur) : un point de restauration est créé automatiquement avant chaque série de modifications (au plus un toutes les 10 minutes), à la demande (« + Créer un point ») et avant chaque restauration ; 30 conservés dans `.studio/` (non publiés) ; comparaison section par section avec l'état actuel.
- **Graphique (modèle de décision)** : « / graphique » → collez vos données (« libellé ; valeur », « libellé ; avant ; après », ou « 2019 ; valeur » pour une évolution), un titre, une unité, éventuellement une intention et une source. Le modèle classe les formes selon vos données (badges « neuve », « N× déjà ») ; l'aperçu vivant utilise le moteur du dossier ; la conversion vers une autre forme garde vos valeurs (Claude, contrôle des nombres perdus). Sans source, les données sont marquées « affirmation ».
- **Dossier vierge** : Crée `content/articles/<slug>/` (squelette : couverture, sommaire, 2 sections, registre de sources vide ; marqué `createdInStudio`) en **brouillon** et l'ouvre dans l'éditeur. Le moteur d'affichage (styles, graphiques, d3) est partagé dans `content/articles/_template/build/` ; rien n'est copié par article. Les dossiers importés avec `pnpm articles import` restent du code ; seuls les dossiers `createdInStudio` sont publiables depuis le studio.

## Édition en place (portfolio et articles : même méthode)
Sur toutes les pages, l'édition est active par défaut dans le studio (bouton « Édition active » pour la couper). Cliquez un texte : il devient éditable à sa place, curseur à l'endroit du clic ; **Entrée** ou un clic ailleurs enregistre dans le brouillon, **Échap** annule (**Ctrl/⌘ + Entrée** pour les textes à plusieurs lignes). Cela vaut aussi pour les liens, boutons, étiquettes et éléments mêlant texte et icônes. Une valeur partagée (société, catégorie, étiquette…) demande après saisie si elle change partout ou seulement ici. Les textes d'attributs invisibles (alt, placeholder, aria-label) s'éditent dans un petit champ posé sur l'élément. En édition, un clic sur un lien ne quitte plus la page. Sections : survol → barre ↑ ↓ / copier / masquer / + Section, comme sur les articles.

## Studio toujours en ligne, sans commande à lancer
Le studio en ligne (section « Mise en place ») n'a **aucune commande à lancer** : c'est un site Vercel comme le public, protégé par Vercel Authentication, qui lit et écrit le brouillon dans la branche GitHub `studio-draft`. Il fonctionne même ordinateur éteint.
- **Avant de le mettre en ligne : passer le dépôt GitHub en privé** (Settings → General → Danger zone → Change visibility). Sinon la branche `studio-draft` et les dossiers d'articles non publiés sont lisibles par tout le monde.
- Il faut committer et pousser `content/` (y compris `content/articles/<slug>/` : `article.json`, `build/`) : le studio en ligne lit les articles dans le dépôt.
- `next.config.mjs` inclut le moteur d'édition des articles (`lib/articles/*.js`) dans la fonction serverless de `/api/studio/view`.
- Alternative locale (ordinateur allumé seulement) : un agent macOS `launchd` qui lance `STUDIO_MODE=1 pnpm start` à l'ouverture de session.

## Assistant d'écriture (Claude) dans l'éditeur en place — studio seulement
Dans n'importe quel texte modifiable : cliquez, sélectionnez tout le texte (⌘/Ctrl + A) et **tapez une demande** (« reformule en plus court », « traduis en anglais », « écris une introduction sur… »). Dès qu'elle ressemble à une consigne (commence par « / » ou par un verbe d'ordre), une pastille propose **↵ envoyer à l'IA · Échap : garder comme texte** ; rien n'est envoyé sans cette confirmation. Pour un texte à plusieurs lignes : ⌘/Ctrl + ↵.
- Votre demande **disparaît** et le texte de Claude prend sa place ; Claude reçoit aussi le texte d'avant (pour les reformulations) et le nom du champ.
- Le texte écrit par l'IA est **souligné en pointillé violet** (gris s'il a été modifié depuis). Au **survol** : votre demande, le texte d'avant, **Annuler l'IA** (rétablit le texte d'avant) et **Marquer comme relu**.
- La fenêtre « Publier » signale combien de textes écrits par l'IA n'ont pas été relus.
- Les traces sont dans `.studio/ai-trace.json` (dossier local, ou branche `studio-draft`) : **jamais publiées**, et le site public n'affiche rien de tout cela.
- Configuration : `ANTHROPIC_API_KEY=<clé>` (en local dans `.env.local`, déjà ignoré par git ; en ligne uniquement dans les variables du **projet studio**). Facultatifs : `STUDIO_AI_MODEL` (défaut `claude-sonnet-5-5`), `ANTHROPIC_API_URL`. Sans clé, la pastille indique « IA indisponible ». Plafond : 60 demandes par heure.
- Confidentialité et coût : le texte du champ, votre demande et le nom du champ sont envoyés à l'API Anthropic à chaque demande confirmée ; chaque demande est facturée. Si le dépôt est public, les demandes stockées dans `studio-draft` seraient lisibles : passer le dépôt en privé avant d'utiliser le studio en ligne.
- L'assistant fonctionne aussi dans l'éditeur des articles/dossiers (même geste : instruction → ↵ → texte remplacé, souligné en violet ; survol = votre demande, « Annuler l'IA », « Marquer comme relu »). Les traces vivent dans `.studio/ai-trace.json`, jamais publiées. L'assistant ne s'applique pas aux textes contenant des pastilles de source.

### Créer de zéro avec Claude
- **Une section** : « + Section » → **✨ Écrire cette section avec Claude…** → décrivez-la (type au choix ou laissé à Claude : titre, texte, image + texte, cartes, citation, appel à l'action, liste). Claude renvoie un bloc validé (types et champs autorisés, liens filtrés, aucune image) qui est inséré après la section survolée ; chaque texte garde sa trace et son soulignement violet (qui apparaît après quelques secondes, ou au rechargement).
- **Un essai** : formulaire « Essais (blog) » → **✨ Nouvel essai avec Claude** → décrivez la thèse, le ton, la longueur. Claude écrit un brouillon (titre, accroche, parties, paragraphes, listes) ajouté **en tête de la liste**, avec `published: true` dans le brouillon : il n'est public qu'après « Publier ». Claude n'invente ni chiffres ni sources (il laisse « [source à ajouter] »). Titre, accroche et paragraphes sont soulignés en violet jusqu'à relecture.
- Une trace n'est affichée que si le texte actuel en vient encore : si vous déplacez ou supprimez des éléments, des marques peuvent disparaître (le texte, lui, reste correct).

### Proposer d'autres graphiques (articles / dossiers)
Dans un dossier ouvert dans le studio (`/articles/<slug>`), survolez une figure → **✨ Autres graphiques**.
1. Le **modèle de décision** du skill `dossier-article` (18 intentions, règles fines : nombre d'éléments, valeurs négatives, temps, incertitude…) classe les formes compatibles avec les données de la figure. Le score favorise les formes **neuves** et pénalise celles des deux derniers articles ou déjà très employées (badges « neuve », « N× déjà »). Sans clé IA, la liste est disponible quand même.
2. **Prévisualiser** : Claude convertit les **mêmes données** vers la forme choisie (même valeurs, mêmes étiquettes, mêmes `src` ; aucune donnée inventée). Le serveur contrôle le résultat (type cible, clés de source existantes, taille) et signale les **valeurs de l'original non retrouvées**. L'aperçu est dessiné par le vrai moteur dans une fenêtre ; rien n'est enregistré.
3. **Appliquer ce graphique** remplace la figure dans le brouillon (`content/articles/<slug>/edits.json`, clé `figures`) : copie privée **et** build public utilisent la figure remplacée. **Rétablir la figure d'origine** annule. Le texte « Lecture » sous la figure n'est pas réécrit : à relire.
- Les figures Lieflat (iframes) ne sont pas convertibles.
- Mise à jour du modèle : après avoir modifié le skill, `node ~/.claude/skills/dossier-article/scripts/export_chart_model.mjs` recopie modèle de décision, traits, historique et contrats dans `lib/articles/chart-model/`.
